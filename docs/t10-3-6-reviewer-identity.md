# T10.3.6 reviewer identity binding

Migration 018 requires each reviewer PostgreSQL login to have an administrator-managed binding to one application user. The authenticated ingestion entry point resolves the synthetic token subject to a user UUID. PostgreSQL verifies that UUID against the login name and role OID of the original session, including after the application switches to the shared reviewer role. The publication owner alone can call the internal write function among the service roles. The existing permission, reviewer grant, freshness and publication checks still apply.

Provision a dedicated restricted login for each reviewer. Grant it membership in `lavlah_ingestion_reviewer` only, and register its catalog role OID, name and application user UUID in `lavlah.reviewer_login_bindings` using a trusted administrator connection. Configure that reviewer's worker with its own `LAVLAH_REVIEW_DSN` and pass the login name as `review_login` when constructing `AuthenticatedIngestion`. The constructor defaults to the existing synthetic CI login. Migration 018 creates an empty binding table, so strict review is denied until provisioning. Removing a binding blocks subsequent checks. An in-flight transaction that already passed the check may finish. Re-provision after a login rename, recreation or restore to another cluster because role OIDs are cluster-specific. The down migration restores the T10.3.5 review boundary.

A01, A02, A05 and A12 remain open. Track trusted login and identity credential provisioning, older definer ownership, authorization expiry between the final check and commit, independent review, and remaining supply-chain hardening. Production remains NO-GO. Validation uses disposable synthetic fixtures.
