# Scheduled collection
Operator registers permission and a disabled collection job; enable only after approval. Provision one JSON file named by permission UUID in a trusted directory. Run `python -m lavlah.collection` using LAVLAH_INGESTION_DSN and LAVLAH_FEED_DIR. Example cron (not installed): `*/15 * * * * /opt/lavlah/run-collection.sh` with an operator-managed wrapper providing environment and working directory. Database due times enforce 1–7 day collection intervals; failed attempts back off from 15 minutes, capped at the job interval. Jobs use row locks and skip locked. Errors are recorded as bounded codes, not raw source text or secrets. A batch is atomic.
 
Local adapter reads operator-provisioned files only; no live HTTP fetch or source registration. The operator must ensure files represent newly observed, authorized data; repeated stale files must not be treated as new evidence. Same-day exact duplicates are suppressed; a later daily observation creates a new candidate requiring independent human review. Cross-source grouping uses an administrator-assigned organization ID and exact content digest, not fuzzy identity matching; it does not delete provenance or automatically merge entities. Permission expiry hides published records and blocks scheduled collection. No automated publication. Production adapter, signed feed observation time, trusted actor binding, service deployment, monitoring and scheduler activation remain gates. Rollback refuses to discard repeated observation history.
