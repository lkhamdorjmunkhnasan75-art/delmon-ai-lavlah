Migration 015 adds narrow SECURITY DEFINER boolean helpers with fixed pg_catalog search path, fully qualified tables, no public execute, and execute only for collector/reviewer roles. Strict ingestion checks acquire FOR SHARE locks on active permission and exact actor capability rows. Admin UPDATE/DELETE conflicts with these locks until transaction end. Existing permission advisory lock remains, and permission expiry is rechecked after locking. No additional UPDATE privilege is given to service roles. Reviewer INSERT grants on review and publication audit tables are narrowed to application-written columns; server-generated reviewed_at and recorded_at cannot be set directly. Rollback restores previous grants and removes helpers. CI applies/up-down-up before backup/restore and pilot schema dump.

Five new DB tests in existing ingestion integrity suite cover revoked reviewer grant, denied direct review timestamp with successful authorized review, denied request-role helper execution, review-first concurrent permission update and grant deletion (lock timeout), and admin-first permission revocation causing pending review denial with no audit row. Existing test code retained. Test synchronization uses events and bounded waits; admin-first case establishes ordering but does not independently prove the worker reached a database lock wait before commit. No external source or identity provider.

Semantics: already-authorized transaction can commit before revocation takes effect; revocation is not retroactive. Locks prevent concurrent changes to the checked rows while the transaction holds them; expiry can pass during the transaction. Network fetching is outside the final HTTPS write transaction; reauthorization remains required. Legacy non-strict integration paths unchanged. Service roles remain trusted and can still write other granted fields directly, including reviewer identity and publication; this is not comprehensive DB enforcement. Collector grant is checked on submit, reviewer grant on review; collector revocation after submission does not invalidate an existing candidate. Membership revocation concurrency and role/physical isolation remain open. SECURITY DEFINER owner and grant audit and deadlock/load testing remain necessary.
