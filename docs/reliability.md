# Reliability hardening
Every HTTPS request through collect_registered now reserves a universal 60-second bucket plus exact host and configured administrative group. This intentionally limits throughput globally; group mappings are administrator-managed, not inferred from public suffixes. Reservation is committed before I/O. No real endpoints are enabled by this change.
A successful observation carries a unique scheduler run ID in the same transaction as candidates. Recovery reconciles committed observations as success and uncommitted expired runs as interrupted. Historical runs without links cannot be retrospectively reconciled. Private alerts expose expired leases, repeated failures and recent interruptions; CLI emits them as JSON, not external notifications.
Transport uses a spawned child and bounded result file, avoiding partial pipe reads; the deadline includes process startup and join, with up to one second cleanup overhead. OS/filesystem stalls and orphan process supervision remain deployment gates.
CI exercises eight concurrent independent DB sessions in threads (not a multi-host process benchmark), commit-before-finish recovery, alerts, previous timeout tests, and logical pg_dump/pg_restore into a fresh disposable database on the same CI cluster. Restored rows and selected privileges are compared. Cluster roles, encrypted offsite backup, disaster recovery RPO/RTO and live egress/identity review remain release gates. No production backup, live collection or scheduler activation.
